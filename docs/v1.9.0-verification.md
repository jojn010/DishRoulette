# Tabkha v1.9.0 verification

## Scope and compatibility

Version 1.9.0 uses versionCode 37. The Android Studio checkout includes the latest main-branch Arabic duration normalization and inactive-timer fixes before this refactor. Application identity, stored preference keys, recipe JSON fields, recipe IDs, cooking progress keys and the encrypted credential format are retained.

Home creation, responsive measurement and refresh work now have named sections. Preferences use their own transactional dialog. Cooking has explicit workspace state and separate instruction-parsing/display-text helpers. Legacy class names have been replaced with pantry/recipe terminology. Java source and tests use a checked-in Android Studio style; `tools/format-java.sh` reapplies it.

Removed superseded source files, unused imports/helpers and duplicated request construction. Retained the optional backend, old-save bilingual recipe library, licensed assets, provisioning tools and historical verification documents. Lint found no additional unused resources to remove. Generated/private files remain ignored.

Allocation changes are directly inspectable: unchanged Home chips and goal controls are reused, stable icons/styles are retained, preferences and translated recipes use explicit independent copies instead of JSON round trips, photo additions scan for empty slots without repeated saved-list copies, and three provider flows share an HTTP connection pool. No device latency or memory percentage improvement is claimed.

## Build and local tests

```sh
./gradlew assembleDebug assembleDebugAndroidTest assembleRelease lintDebug \
  :app:testDebugUnitTest :recipe-core:test :backend:test --offline --console=plain
```

Debug and optimized release builds pass. **77 JVM tests pass**: app 42, recipe-core 17 and backend 18. New checks cover preservation of every serialized recipe fact during language selection, independent mutable copies of preferences/recipe text, response byte bounds and request header/redirect configuration.

Lint: **0 errors, 0 unused resources, 12 advisory warnings**. These concern dependency/catalog maintenance and two intentionally programmatic view constructors. This refactor retains dependency versions.

## Live provider checks and workspace

The owner connection was provisioned into the emulator's encrypted store after all fixture tests. Live English recipe generation and legacy translation passed. Arabic generation first returned `PROVIDER_UNAVAILABLE`, then a response rejected as `INVALID_RECIPE`. A separate raw Arabic request returned HTTP200 and passed the same core validation, including matching primary Arabic text and parallel language counts. The final Android Arabic generation check passed. These attempts demonstrate variable provider responses; validation was not relaxed to obtain a pass.

The ordinary debug APK is installed on the emulator with the existing signing identity. Android Studio was opened on `/home/jojn10/AndroidStudioProjects/DishRoulette`. The separate Documents checkout and its report artifacts were left intact.

## Limits

Tests cover representative emulator paths, not every physical device or future provider response. Timers remain foreground visual timers. Recipe generation and historical translation depend on the configured provider; nutrition remains estimated. Local debug signing is suitable for updating the existing development installation; the optimized release build is unsigned. Private owner connection material is excluded from uploaded artifacts. Both ordinary APKs were inspected for the private bootstrap asset and locally configured key; neither is present. The debug APK retains the existing signing certificate for compatible development updates.
