# v1.1.0 verification

Native Android upgrade on the existing project and private repository. No web/iOS port or cloud backend deployment is included.

## Architecture

`MainActivity` remains the shared coordinator for recipe requests, validation, preferences and saved recipes. `IngredientLoadout` adapts the shared `IngredientMagazine` to either `NativeIngredientLoadout` / `SimpleHomeView` or the existing `WeaponInputView`. Simple mode constructs neither the GL view/renderer nor mechanical audio. `KitchenScreens` shares saved recipes, settings and cooking with theme attributes for the selected presentation.

Android string resources and configuration locales provide localization. Language and interface preferences are independent. Arabic uses bundled Cairo with its OFL license, native RTL controls and shaped StaticLayout text for 3D cartridge textures. The scene remains LTR. Canonical API enums/keys remain English while generated display fields follow the requested language. Existing saved content is never translated in place.

Common food aliases are bounded and shared between client/backend. Arabic exclusion aliases supplement the existing heuristic screening; these are not comprehensive translation or allergy certification.

## Checks

- Debug build, release build, Android lint.
- 38 JVM tests: 19 app, 12 backend, 7 shared recipe-core.
- 19 deterministic device scenarios passed (runner reports 21 including two skipped live-only methods). Existing gesture, ingredient interaction, waiting/cancellation, recipe, saved archive, cooking checklist, timer and reduced-motion instrumentation.
- Dual-interface instrumentation: no GL in Simple; English and Arabic input/results; all four interface/language combinations; settings persistence and saved/ingredient preservation; fresh-install/legacy defaults; Advanced Arabic generation and Simple Surprise through the shared service.
- Opt-in real Gemini English/Arabic generation, saving and cooking passed end to end (one test covering both languages). These use API quota and can fail with provider/transport errors independently of deterministic UI tests.
- Rendered emulator inspections: standard phone, narrow phone and wide Android window; English/Arabic Simple and Advanced. Device under test is the Android 14 emulator only; the connected physical phone is untouched.
- Complete Arabic string resource coverage, diff whitespace review, source credential-pattern scan and exclusion of local keys/build artifacts from Git.

## Practical limits

Recipe generation needs the existing local development backend and port forwarding; the release configuration deliberately has no public endpoint. The downloadable debug APK uses the same local service. Timers persist in-app but have no background alarm. This release supports Android phones/tablets/resizable windows, not iPhone or browser deployment. AI responses remain subject to service availability and strict validation. No generated recipe photographs are fabricated.
