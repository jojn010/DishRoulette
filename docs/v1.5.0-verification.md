# v1.5.0 automatic owner connection

The owner's key is supplied through ignored local configuration. It is not in GitHub history,
source, release notes or the public APK. The Windows build script creates an owner-only APK,
then rebuilds ordinary output without the bootstrap asset. The private APK imports credentials
into Android Keystore storage on first launch; existing saved credentials take precedence.
Home has no Connect Gemini call to action. Settings retains recovery and replacement controls.

Validation: Gemini model access succeeded. Public/private builds, Android unit tests, recipe-core
and backend tests, and Android lint passed. The opt-in PrivateConnectionTest passed on the
API 37 emulator: first-launch automatic import matched the private bootstrap and a real direct
Gemini recipe request returned a recipe with validated nutrition estimates.

Run locally on Windows:

```powershell
$env:JAVA_HOME='C:\Program Files\Android\Android Studio\jbr'
$env:ANDROID_HOME="$env:LOCALAPPDATA\Android\Sdk"
./tools/build-private-apk.ps1
```

Install `work/private/Tabkha-personal.apk` for the auto-connected owner experience. This file
contains an extractable API key and must remain local. `app/build/outputs/apk/debug/app-debug.apk`
is the credential-free public release. Both use the same workstation signing key as v1.4.0.

The two-hour heartbeat tests English/Arabic and uses an available emulator for useful, verified
improvements. The heartbeat tool does not expose model/reasoning settings; the user's Sol/Astra
preference is recorded in its instructions but is not an enforced scheduler setting.
